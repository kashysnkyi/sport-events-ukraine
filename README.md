# Система управління спортивними подіями

Sport Events Ukraine - навчальна реалізація на PostgreSQL 15+ і .NET 8 у форматі відкритого каталогу спортивних подій України. Проєкт містить 17 сутностей, ER-модель, soft delete, аудит змін, функції, тригери, подання, індекси та приклад Repository + Unit of Work.

## Артефакти

- `sports_events_portal.dbml` - нова ER-модель порталу для імпорту/перегляду на [dbdiagram.io](https://dbdiagram.io/).
- `sports_events.dbml` - попередня ER-модель, залишена для порівняння.
- `schema.sql` - повна схема PostgreSQL, прикладний API з 14 функцій запису/читання, тригери, подання та індекси.
- `seed.sql` - повторюваний демонстраційний набір даних: 12 подій, 14 локацій, 8 команд, 300 профілів спортсменів, заявки, змагання, матчі та спонсори.
- `repository-example.cs` - приклад .NET 8 з Dapper/Npgsql. Команди й читання проходять через функції/подання БД.
- `sports-events-app/` - консольний клієнт .NET 8 з Repository + Unit of Work для подій і реєстрацій.
- `requirements.md` - короткі функціональні вимоги та обґрунтування сутностей.
- `NORMALIZATION_AND_INDEXES.md` - пояснення 1НФ, 2НФ, 3НФ, усунення аномалій та перевірка індексів.
- `index.html` - готовий клікабельний портал у стилі каталогу турнірів: каталог, пошук, фільтри, календар з перемиканням місяців, результати, картка події, вибір категорії, кабінети учасника й організатора, підтвердження заявок, профілі та створення події.
- `assets/app.js` і `assets/styles.css` - окремі файли логіки та стилів прототипу.

## Запуск

Створити порожню БД PostgreSQL, наприклад `sports_events`, та виконати:

```bash
psql -d sports_events -f schema.sql
psql -d sports_events -f seed.sql
```

У pgAdmin відкрийте Query Tool для бази `sports_events`, виконайте спочатку `schema.sql`, а потім `seed.sql`. Наприкінці seed-скрипт повертає контрольні кількості основних об'єктів. Скрипт можна виконувати повторно: записи мають стабільні ідентифікатори та оновлюються через `ON CONFLICT`.

Потрібні розширення `pgcrypto` і `pg_trgm` (створюються на початку скрипту). Приклад коду потребує пакетів `Npgsql` та `Dapper` і рядка підключення через `SPORTS_DB`. У PostgreSQL процедурний API реалізовано SQL/PLpgSQL-функціями (`SELECT sports.fn_...`), оскільки вони повертають ідентифікатори та статус операції.

Для клієнта потрібен .NET 8 SDK. Задайте змінну `SPORTS_DB` зі своїм рядком підключення і виконайте `dotnet run --project sports-events-app -- list`. Додаткові команди: `register <categoryId> <athleteId> <actorId>` та `cancel <registrationId> <actorId>`. Створення події, категорії та публікація виконуються в одній транзакції через `EventWorkflow.CreateAndPublishAsync`.

Для перегляду порталу запустіть `python -m http.server 8765` і відкрийте `http://127.0.0.1:8765/index.html`. Демонстраційний каталог містить 12 подій у 7 містах України, з них 10 мають відкриту реєстрацію, 2 завершені та мають результати. Додано 5 видів спорту та 300 різних профілів учасників. Доступні демо ролі організатора та учасника, вхід, вихід, вибір однієї категорії під час реєстрації, календар з переходом між місяцями, результати, профіль заявки, кабінет організатора з підтвердженням або відхиленням заявок, список учасників і створення нової події. Створена подія одразу відкривається в каталозі та відновлюється після оновлення сторінки.

## Межі прикладу

Скрипт задає основу для навчального проєкту, а не повну production-систему: автентифікація та права на ролі застосунку, платіжний контур, часові пояси локацій, конкуренція за останнє місце з блокуванням рядків та правила конкретних федерацій додаються окремо. Зміни сутностей проходять тригером аудиту; `last_modified_by` передається застосунком через `app.current_user_id` у транзакції.
